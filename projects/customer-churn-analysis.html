Customer Churn Analysis

To analyze telecom customer data for identifying churn patterns and predicting attrition risks using Python and machine learning. The goal was to empower retention strategies through data-driven insights and interactive dashboards.

B1

Problem

Lenders need a fast, consistent way to flag which loan applications are likely to be approved before manual underwriting, reducing turnaround time and inconsistent decision-making across reviewers.

B2

Data

    1. Imported the Loan-Approval data from Kaggle.in
    2. Consisting of 614 records of costumers with 13 features.
    Features -->

  • Loan ID
  • Gender
  • Married
  • Dependents
  • Self_employed
  • Education
  • Applicant_Income
  • Co-Applicant_Income
  • Loan_Amount
  • Loan_Term
  • Credit_History
  • Property_Area
  • Loan Status
    • B3

    Approach

      1. Data Cleaning -->
  • Checked nulls (Gender, Married, Dependents, Self_Employed, Loan_Amount_Term, LoanAmount, Credit_History all had missing values).
  • Filled categorical nulls with mode (loop over 5 columns), LoanAmount with median, Credit_History with mode.
      • 2. Exploratory Data Analysis -->
  • Loan status distribution (countplot)
  • Applicant income by education level (boxplot)
  • Loan approval by property area (countplot, hued by status)
      • 3. Feature Engineering -->
  • Converted Dependents ('3+' --> 3) to float
  • Created Total_Income (Applicant + Coapplicant income) and Income_To_LoanRatio
  • Label-encoded categoricals (Gender, Married, Education, Self_Employed, Property_Area) and the target (Loan_Status: Y/N → 1/0)
  • Dropped Loan_ID
      • 4. Modelling
  • 65/35 train-test split
  • Trained 4 models: Logistic Regression, Random Forest, Decision Tree (max_depth=4), XGBoost
  • Applied SMOTE to fix class imbalance, then retrained Random Forest on the resampled data

    • B4

    Results

  • Class imbalance found: 422 approved vs. 192 not approved. SMOTE balanced this to 422/422 for the retrain.
  • Logistic Regression: 92% accuracy (perfect precision/recall on all 215 test samples)
  • Decision Tree: 86% accuracy
  • XGBoost: 85% accuracy
  • Random Forest (post-SMOTE): 83% precision/recall/F1

    • B5

    Key takeaway

    The biggest lesson wasn't a modeling technique — it was learning to distrust results that look too good, and treating unrealistic accuracy as a signal to dig into the data pipeline rather than the algorithm.
